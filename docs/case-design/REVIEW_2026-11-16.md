Written 2026-11-16 by Claude, read-only on Codex's files. Split proposed by Codex: Codex does the Godot integration; Claude checks
dialogue, design consistency and stale documentation. Everything here was checked against the main folder as it stood that day
(about 430 uncommitted files, nothing pushed after tag `v0.1.4`).

## 1. Generator parity: exact

`src/mystery/generated_case.gd` against `tools/case_design/generate.py` (version 2): I dumped 900 cases from Godot headless
(3 difficulties x suspect counts 4-8 x seeds 0-59) and compared every field with the Python reference: cast, personalities, rooms,
claims, culprit, murder room, weapon room, glass room, trace mode, guest start. **900 of 900 identical, zero mismatches.** The
port also keeps the rules: murder room never in the secret room, weapon and glass may be there only on Hard, decoy 0 / 0.5 / 1.
Codex's own checks do not assert Python parity; this check should become a fixture test (I can export the JSON).

Differences to know about:

- **Time costs.** The runtime counts only walking steps (`action_steps` 0, `portal_steps` 0). My simulator charged 2 steps per
  action and 10 per room-to-hall leg, so its win-rate table (`GENERATOR_SPEC.md` section 11) no longer describes the game. Re-run
  `simulate_clock.py` with the runtime's costs before using it for tuning.
- **Guest movement model.** The runtime resolves relocation only on room entry (`1-(1-0.01)^elapsed`); my simulator moves guests
  every tick. Same rate, different timing; the simulator is conservative for Hard.
- **Two house-02 files.** `house-02.layout.json` (byte-identical to mine, with guest spots, kinds and facings) feeds the
  investigation; `house-02.painted.layout.json` has Codex's re-tidied furniture and **no guest spots**, so `-Painted -Investigate`
  is refused. The kinds and facings I generated are not used by painted rooms yet.
- **Front Entry labels.** My `auto_label` tagged its two side blocks `stairs`; the user said they are pillars or statues. The
  `stairs` labels in `house-02.layout.json` (and the spot kinds that depend on them) are wrong and should be changed.

## 3. Dialogue: written, not used

The runtime uses placeholder text. There is **one fixed opening line per personality** (`VOICE` in `house_case_session.gd`) and a flat
"I was in the X, with Y". None of the 864 lines in `assets/dialogue/` (18 line types x 8 personalities x 6 variants, plus the 20
system keys and 5 rank titles) is loaded, because that folder exists only on `design/case-generator`, which is local and unpushed.

- **Original wording.** Two runtime strings are close paraphrases of the original game's text: "The murderer has grown suspicious"
  (`house_runtime.gd:67`) and "The murderer is stalking you" (line 68); the death scene line "grabs the X from your hands" is also
  near the original. The project rule is original wording only. `system.json` already has replacements (`warning_suspicious`,
  `warning_stalking`, `ambush_grab`, `ambush_locked`) that pass the validator.
- **Missing text surfaces.** Refusal lines (22% refusals), repeat-question lines, commentary about victim and other suspects,
  the five confession tones, culprit-corrects lines, rank titles and the floor / weapon / assemble messages all exist in my data
  and are not wired in.
- **What integration needs.** Data only: load `personalities.json` and `system.json`, render slots (`{speaker}`, `{room}`,
  `{partner}`, `{victim}`, `{weapon}`...), pick a variant by seeded stream. `DIALOGUE_SCHEMA.md` has the contract and
  `compose_reply()` in `tools/case_design/dialogue.py` is the reference. Spot and personality data stay separate (decided).
